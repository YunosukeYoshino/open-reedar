# Reedar

<img src="assets/icon.png" alt="Reedar: an open book with RSS arcs on a graphite tile" width="128" height="128">

**静かな RSS リーダー。すべての記事と対話する。**

[![CI](https://github.com/YunosukeYoshino/open-reedar/actions/workflows/ci.yml/badge.svg)](https://github.com/YunosukeYoshino/open-reedar/actions/workflows/ci.yml) [![Release](https://img.shields.io/github/v/release/YunosukeYoshino/open-reedar?include_prereleases)](https://github.com/YunosukeYoshino/open-reedar/releases) [![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Reedar は macOS 向けのデスクトップ RSS リーダーです。なじみのある3ペインの読書体験を目指しています。フィードを購読して記事を整理し、お使いのコーディングエージェントに記事の理解を手伝ってもらえます。

CLI のログインをそのまま使います。Reedar はエージェントの既存のサービスアクセスと利用枠を使用し、別途モデル API キーを必要としません。

> **Apple Silicon 版 macOS 向けアーリープレビュー。** Codex による読書は GPT-6-Luna で検証済みです。Claude Code の実環境での読書は未検証、Antigravity の読書は無効化しています。インターフェースと読書アシスタントは英語・日本語対応で、エージェント接続ダイアログで言語を切り替えられます。
>
> **ダウンロードに関する制限:** DMG / ZIP プレビューはアドホック署名で、**公証されていません**。macOS がダウンロードしたアプリをブロックすることがあります。別の Mac でのインストールと Intel での実行は未検証です。ビルドをインストールする前に [Distribution](docs/distribution.md) をご覧ください。

## 機能

- **3ペインリーディング:** フィードとフォルダ、記事リスト、記事本文。
- **自分だけのライブラリ:** RSS / Atom の直接購読、フォルダ、未読フィルタ、スター、ダウンロード済みのタイトルと本文の検索。購読を削除しても記事や会話を保持したまま復元できます。
- **購読の持ち運び:** フォルダ所属、重複検出、進捗表示、キャンセル、フィードごとの結果表示に対応した OPML インポート/エクスポート。
- **エージェントと読む:** 選択した記事の要約や追加質問を、回答がストリーミングされる形で行えます。
- **記事に残る会話:** ローカル履歴には会話に使用したソーステキストのスナップショットが含まれます。
- **明確な実行状態:** running / waiting / completed / failed / cancelled の状態と、部分回答を保持したまま止められる停止ボタン。
- **キーボード操作:** キーボードだけで記事間を移動し、既読状態を管理できます。
- **ターミナルとエージェントハーネス:** `open-reedar` CLI がフィードの未読状況を一覧し、記事を表示・要約します。ワンクリックのインストーラが Claude / Codex / 汎用エージェントのスキルディレクトリにスキルを配置し、コーディングエージェントから呼び出せます。

AI へのリクエストは明示的で、選択した記事にのみ適用されます。AI の利用は記事の既読状態を変更しません。

## はじめに

### 要件

- macOS。他のプラットフォームは未検証です。
- ダウンロードプレビューは Apple Silicon 向けです。
- AI 読書には、対応する CLI がインストールされ、要求するモデルへのアクセス権を持つアカウントでサインイン済みである必要があります。フィードの読書には AI ログインは不要です。

### プレビューのインストール

[v0.2.0 リリース](https://github.com/YunosukeYoshino/open-reedar/releases/tag/v0.2.0) から DMG をダウンロードし、開いて Reedar を Applications にドラッグしてください。同じアプリを含む ZIP もあります。Bun やソースチェックアウトは不要です。リリースには SHA-256 マニフェストが付属し、上記のプレビュー制限が適用されます。

### デスクトップアプリの実行

開発には Bun（現在のベースラインは **1.4.2**）をインストールしてください。テストスイートは一時ファイル削除のため `trash` が `PATH` 上に必要です。ローカルチェックアウトから:

```sh
bun install --frozen-lockfile
bun run start
```

インストール時に Electron をダウンロードします。start コマンドはレンダラーとデスクトップエントリをビルドして Reedar を開きます。ローカルでの DMG / ZIP プレビューは `bun run dist:mac --arm64` でビルドできます。Developer ID 署名済みリリースはまだ提供していません。[Distribution](docs/distribution.md) をご覧ください。

### アプリの更新（0.2.0 開発ビルド）

デスクトップアプリは起動 30 秒後と、起動中は 6 時間ごとに公開 GitHub リリースを確認します。**Reedar → アップデートを確認…** で即時チェックも可能です。このプレビューは現在の Mac アーキテクチャ向けの新しい公開リリースとプレリリースを受け取り、ダウングレードはしません。

アドホックプレビューは通知してリリースのダウンロードページを開きます。Developer ID 署名済みビルドは自動で更新をダウンロード・検証し、再起動を提案します。**あとで** を選ぶとアプリを開いたままにし、ステージされた更新は次回の通常終了後に適用されます。再起動時は実行中の AI 応答と OPML インポートを停止し、それまでの結果を先に保存します。開発実行では更新チェックを行いません。

**公開済みの 0.1.2 にはアップデータがなく、手動での入れ替えが必要です。** アドホックプレビューから移行する場合、最初の Developer ID 署名済みバージョンも手動インストールが必要です。署名済みアプリの実際の更新は未検証です: Developer ID Application 証明書と公証クレデンシャルの整備が残っています。必要なリリースアセットと署名設定は [Distribution](docs/distribution.md#app-update-delivery) を参照してください。

### 最初のフィードを追加

1. サイドバーの **+** をクリックして RSS または Atom の URL を入力します。
2. 記事を選択して読みます。ツールバーでスターや未読マークを切り替えられます。
3. **AIと読む** を開いてエージェントを選び、質問を送信するか要約ショートカットを使います。

Reedar は最初、フィードが提供するテキストを表示します。回答や要約の前に、リンク先の HTML ページを取得して記事本文をローカルで抽出します。**要約する** ボタンはメインのリーダーにストリーミング要約を表示し、**フィード本文に戻る** でフィード表示に戻ります。AI に送られたテキストは要約の下で確認できます。

取得に失敗したりフィードより短いテキストしか取れなかった場合、アシスタントは保存済みのフィードテキストを使い、その制限を明示します。抽出は JavaScript を実行せず、ブラウザの Cookie も使わず、ログインやペイウォールも迂回しません。すべてのサイトで完全な本文を保証するものではありません。追加質問は取得済みのソースを再利用します。通常のウェブページ URL をフィードとして自動登録することはまだできません。

## 購読の管理

サイドバーのフィード見出し横のメニューから **フィードを整理** を開くと、購読の移動や削除ができます。削除したフィードは読書ビューから消え、更新も止まります。キャッシュ済みの記事、スター、会話は保持され、同じダイアログの **削除済みのフィード** から復元できます。フィードの削除は実行中の AI 応答を停止し、部分テキストを保持します。フォルダは同じダイアログからリネーム・削除でき、削除したフォルダのフィードは「フォルダなし」に移動します。

サイドバー下部の **OPML入出力** から:

- UTF-8 の `.opml` または `.xml` ファイルを選択して **OPMLを読み込む**。1ファイルあたり最大 256 KB・200 フィードまで。
- 既存の購読と重複エントリはスキップされます。削除済みの購読は復元されます。一部のエントリが失敗しても有効なフィードは保存され、結果は各フィードごとに表示され、キャンセルもできます。
- フォルダ所属は維持されます。ネストしたパスは `Technology / Web` のような単一フォルダ名になり、60 文字を超えるパスはそのエントリが失敗します。空フォルダはインポートで作成されません。
- **OPMLを書き出す** で有効な購読とフォルダをダウンロードできます。これは購読リストのエクスポートであり、完全なライブラリバックアップではありません: 記事本文、スター、会話、削除済みフィードは含まれません。

外部 OPML のインクルージョンはたどりません。DTD、エンティティ、不正な XML、プライベートネットワークのフィード URL は拒否されます。インポートの進捗は現在のアプリセッション中のみ表示されますが、登録に成功した購読は再起動後も残ります。

## エージェント対応

| エージェント | 状態 | 読書モデル / 挙動 |
| --- | --- | --- |
| **Codex** | 実アカウントで検証済み | GPT-6-Luna を明示的にピン留め。Mac アプリで日本語要約と追加質問を検証済み |
| **Claude Code** | アダプタ実装済み・実環境検証待ち | 認証待ちの挙動は検証済み。実環境での読書成功は未検証 |
| **Antigravity** | CLI 検出のみ | 統合保留として表示。セッション単位のツール制限を強制できるまで記事送信は無効 |

**エージェント接続** を開くと利用可否を確認できます。Reedar の外で CLI にサインインしてから接続状態を更新してください:

```sh
# 使っている CLI を選択:
codex login
claude auth login
```

Codex には ChatGPT ログインと `gpt-6-luna` へのアクセスが必要です。Reedar は CLI が返したモデルを確認し、異なる場合は停止します。別モデルへの暗黙の置き換えは行いません。Claude Code は既存のサブスクリプションログインを使う想定です。リクエストは接続したサービスの利用枠を消費します。

Reedar は OpenAI の Codex デスクトップアプリに同梱の Codex CLI を優先し、次に `PATH` と一般的なインストール場所を確認します。`REEDAR_CODEX_BIN`、`REEDAR_CLAUDE_BIN`、`REEDAR_ANTIGRAVITY_BIN` で実行ファイルを指定できます。Antigravity のオーバーライドは検出のみに影響します。Reedar は既存の CLI 設定を書き換えません。

検証済みバージョン、証拠、統合の制限は [validation record](docs/validation.md) をご覧ください。

## open-reedar CLI

**エージェント接続** の **CLIとスキルをインストール** を選ぶと、`~/.local/bin/open-reedar` にコマンドを配置し、`~/.claude/skills/open-reedar`、`~/.codex/skills/open-reedar`、`~/.agents/skills/open-reedar` にスキルファイルを書き込みます。CLI は `~/Library/Application Support/Reedar/reader.json` を直接読み取ります（読み取り専用。アプリが起動している必要はありません）:

```sh
open-reedar feeds                              # 未読・スター数付きのフィード一覧
open-reedar articles --unread --feed hnrss     # 新しい順の記事一覧
open-reedar article <id>                       # 記事全文（id は前方一致で可）
open-reedar summarize <id>                     # サインイン済みエージェント CLI による要約
```

リスト系コマンドは JSON Lines を出力し、パイプ時は stdout がデフォルトで JSON になり、エラーは stderr に出ます — コーディングエージェントや `jq` パイプライン向けの設計です。`summarize` はアプリのエージェントアダプタを再利用します（Codex または Claude のログインが必要）。ライブラリのパスは `REEDAR_STORE` で上書きできます。パッケージ版には `Contents/Resources/bin/open-reedar` にコンパイル済みバイナリが同梱され、開発インストールは `bun src/cli/open-reedar.ts` へのシムになります。

## キーボードショートカット

| ショートカット | 動作 |
| --- | --- |
| `J` / `↓` | 次の記事 |
| `K` / `↑` | 前の記事 |
| `S` | スター切替 |
| `M` | 既読 / 未読切替 |
| `/` | 記事検索にフォーカス |
| `N` | フィードを追加 |
| `⌘ Enter` | AI 質問を送信 |

入力フィールドに文字を打っている間は記事ショートカットは無効です。

## データとプライバシー

ライブラリはローカルに保存されます:

| モード | デフォルトの場所 |
| --- | --- |
| デスクトップ | `~/Library/Application Support/Reedar/reader.json` |
| ブラウザ開発 | `.data/dev/reader.json` |

2つのモードは別々のライブラリを使います。データにはフィード、キャッシュ済み記事、フォルダ、既読状態、スター、会話が含まれます。ファイルは OS の権限で保護されますが、**暗号化はされていません**。データディレクトリをバックアップする前にアプリを終了してください。

質問を送信すると、選択した記事のテキストとその会話が、選択した AI プロバイダの CLI を通じて送信されます。ローカル保存はモデル推論がローカルであることを意味しません。フィード、記事ページ、画像の取得もネットワークリクエストを行います。デスクトップの更新チェックは GitHub に接続し、署名済みビルドは新しいアプリケーションパッケージもダウンロードします。

読書セッションは記事コンテンツを信頼できない入力として扱い、外部ツールを制限し、権限昇格を拒否します。レンダラーはフィード HTML をサニタイズし、Electron の分離と CSP で動作します。セッション認証されたループバックサーバーはリクエストの Origin と Host を検査し、ネットワーク取得はプライベート宛先を拒否します。

境界とその制限は [Security](SECURITY.md) をご覧ください。

## 開発

```sh
bun run dev        # ブラウザ開発サーバーをビルドして起動
bun run typecheck  # TypeScript チェック
bun test           # 自動テスト（実モデルへのリクエストなし）
bun run build      # レンダラーと Electron のバンドル
bun run check      # 型チェック・テスト・ビルド
bun run dist:mac --arm64  # macOS の DMG / ZIP プレビューをビルド
bun run checksums  # アーカイブのチェックサムマニフェストを書き出し
```

`bun run dev` が出力する URL を開いてください。サーバーは起動ごとに新しいセッションと空きポートを使います。その URL は公開しないでください。このコマンドはファイルを watch しないため、ソース変更後は再起動してください。

デスクトップ・ブラウザ開発ともに `REEDAR_DATA_DIR` でライブラリディレクトリを変更できます。指定しない場合は上記のデフォルト場所を使います。ブラウザ開発では `REEDAR_PORT` でポートも指定できます。普段の購読を変えずに空のライブラリを試すのに別データディレクトリが便利です。

[CI workflow](.github/workflows/ci.yml) はプルリクエストと `main` へのプッシュでこれらのチェックを実行します（実モデルへのリクエストなし）。ホスト側の結果は [GitHub Actions](https://github.com/YunosukeYoshino/open-reedar/actions) をご覧ください。

**Electron・React・TypeScript・Bun** で構築。ソースは `src/main`（デスクトップホストとローカルサービス）、`src/ui`（リーダーインターフェース）、`src/shared`（検証済みデータ契約）にあります。リポジトリマップとワークフローは [Contributing](CONTRIBUTING.md) をご覧ください。

## スコープ

このプレビューには定期フィード更新、ライブラリ全体のバックアップ/復元、会話削除、記事保持期間、複数記事ダイジェスト、[大規模ライブラリのベンチマーク](docs/benchmarks.md)が含まれます。サービス同期、モバイル版、定期的な自動ダイジェスト、Developer ID 署名済みインストーラは対象外です。

[ロードマップ](ROADMAP.md) が完了した作業、公開プレビュー準備、日常リーダー改善、長期的な候補を追跡しています。

ストリーム回答は約1秒ごとに保存します。通常終了・キャンセル・エラーでも受信済みの本文を部分回答として保持します。クラッシュ時は最後の保存以降の差分を失う可能性があり、中断された回答は次回起動時に失敗として記録されます。

記事と注釈は起動時に `articles.db`（SQLite）へ自動移行し、FTS5 でタイトル・フィード本文・リーダー本文を全フィード横断検索できます。フィード・フォルダ・設定・会話は `reader.json` に残し、元データは `reader.json.bak` に保持します。DBを開けない場合は検索を無効にしてJSONとバックアップで起動します。障害中の編集と削除記録は別途保存してDB復旧時に反映し、未編集のバックアップ記事でDBの削除済み記事を復活させません。ファイル単位のバックアップはデータディレクトリ全体を保存してください。

サイドバーのライブラリメニューでフィード・フォルダ・記事・読書設定をエクスポート/復元できます。復元はデータを置換し、HTMLを再サニタイズし、AIジョブを停止して実行中の更新・インポートを待ちます。会話は復元記事と関連するものだけ残します。会話削除は記事を残します。保持期限は古い未読記事を削除し、既読・スター・メモ・ハイライト・最近の記事・実行中のAI対象記事を保護します。

Apple Intelligence は macOS 27 の `fm` CLI を使い、接続画面で既定の `system` または `pcc` を選べます。シリアライズ後のプロンプトが30,000文字を超えると、クラウド送信通知とともに Private Cloud Compute へ切り替えます。PCCの上限は100,000文字です。Apple のダイジェストと分割要約はPCCを既定にし、PCC失敗時はsystemの上限内なら通知付きでフォールバックします。CLI通知はstderrへ出します。長文は最大2回の分割要約・合成を行い、まだ上限を超える場合は切り詰めます。追加のAI呼び出しが発生します。実際の `fm`/PCC は[このVMで未検証](docs/validation.md#apple-intelligence-agent--september-29-2026)です。
